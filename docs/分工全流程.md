# Appium × Artemis 分工全流程

> 目标：回归用 Appium（零 token），探索用 Artemis（消耗 token），各干各的，最省。

## 一、什么时候用谁

| 场景 | 工具 | token | 速度 | 稳定性 |
|---|---|---|---|---|
| 固定流程、元素存在、文本校验 | **Appium** | 0 | 快 | 高 |
| 找元素、自绘界面、自然语言验证 | **Artemis** | 有 | 慢 | 中 |
| 冒烟：核心路径跑一遍 | **Appium** | 0 | 快 | 高 |
| 探索：新页面/新功能探路 | **Artemis** | 有 | 慢 | 中 |

**口诀**：能 Appium 干的，别让 Artemis 干。

> **⚠️ 本机代理坑（已修，原理备忘）**：环境变量 `HTTP_PROXY`（梯子）会劫持发往 127.0.0.1 的请求，代理转发时把请求行改写成绝对 URL，导致 Appium 免代理名单失配、命令被裸代理到手机端报 404。已在 `testcases/conftest.py` 和 `run_full_pipeline.py` 里强制 `NO_PROXY=127.0.0.1,localhost`。如果你自己在别的终端手跑 pytest 遇到 `UnknownMethodException`，先检查代理环境变量。

## 六、写混合用例的模板

```python
import pytest
from common.artemis_client_wrapper import ArtemisWrapper

@pytest.fixture
def artemis():
    return ArtemisWrapper()

# 纯 Appium（零 token）
def test_fixed_assert(driver):
    assert driver.current_activity, "启动后应有 activity"

# Artemis 探索（消耗 token）
@pytest.mark.asyncio
async def test_explore(artemis):
    result = await artemis.explore("打开设置，进入关于手机页", expected_output="关于手机")
    assert result.succeeded, result.error

# 混合接力
@pytest.mark.asyncio
async def test_hybrid(driver, artemis):
    driver.press_keycode(3)                        # Appium 准备环境
    result = await artemis.explore("...")          # Artemis 探索
    assert driver.current_activity                 # Appium 兜底断言
```

## 七、判读标准

- **Appium 回归**：`returncode == 0` 即全绿，任何断言失败都会红并自动截图挂 Allure
- **Artemis 探索**：`result.succeeded == True` 即通过；失败看 `result.error`
- **总报告**：`pipeline_report.html` 顶部两块卡片，绿=通过红=失败
