# 01 · AppAutoTest 方案设计文档

> 版本: v1.0 · 适用: Android / iOS 原生 App 自动化测试 · 语言: Python + Appium + Pytest + Allure

---

## 1. 项目定位与目标

**一句话**: 搭建一套"扔 App 即可测"的双端(Android/iOS)自动化测试平台, 把从装包到报告的全链路标准化, 并沉淀 PageObject 资产, 让用例可以无限累积。

**核心目标**
1. **开箱即用**: 任意 APK/IPA, 一条命令完成「安装 → 启动 → 冒烟 → 截图 → 页面结构 dump → Allure 报告」。
2. **双端同构**: 同一套框架、同一套用例骨架、同一份 Allure 报告; 元素定位用「双端字典」一次描述, 双端取用。
3. **AI 友好**: dump 出的页面 xml + 截图是结构化的第一手素材, 可直接驱动 AI 生成/维护 PageObject 与业务用例(这是本项目与 AI 协作的关键接口)。
4. **可持续**: 分层配置、日志、截图、报告、CI 就绪, 便于多人/长期维护。

## 2. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.9+ | 生态成熟、编写快、AI 生成友好 |
| 客户端驱动 | Appium 2.x / 3.x (appium-python-client) | 跨平台事实标准, Android 走 UiAutomator2 / iOS 走 XCUITest; 服务器统一 `appium server --port 4723` 启动 |
| 用例框架 | Pytest 8 | fixture / 参数化 / marker 隔离 / 生态 |

| 配置 | YAML 双层(global + local) | 团队默认 + 个人覆盖, 深合并 |
| 并行(可选) | pytest-xdist | 多设备/多进程并行 |
| 元素策略 | WebDriverWait + PageObject | 稳定等待, 定位符字典化 |

## 3. 总体架构

见 `docs/02-流程图.md` 图 1, 概要:

```text
┌────────────── 用例层 testcases/ ──────────────┐
│  generic/ 通用冒烟(任意 App)                  │
│  android/ ios/ 业务用例(基于 pages/)          │
├────────────── 页面对象层 pages/ ──────────────┤
│  CalculatorPage ... (继承 BasePage)           │
├────────────── 框架层 common/ ─────────────────┤
│  BasePage · DriverManager · Config · Logger   │
├────────────── 执行底座 ───────────────────────┤
│  Appium Server (uiautomator2 / xcuitest)      │
│  设备: Android 模拟器/真机 · iOS 模拟器/真机   │
└───────────────────────────────────────────────┘
        ↓ 产物
   allure-results/ → Allure Report
   reports/dumps/*.xml → 页面结构(喂给 AI)
   screenshots/*.png → 视觉证据
   logs/autotest.log → 运行日志
```

### 3.1 各模块职责

| 模块 | 职责 |
| --- | --- |
| `common/config.py` | 读 YAML; global/local 深合并; 运行期 CLI 覆盖; App 路径解析 |
| `common/driver_manager.py` | 组装双端 capabilities; 设备探测(adb); 会话单例创建/退出 |
| `common/base_page.py` | 定位符解析(双端字典/简写); 查找/点击/输入/滑动/等待; 截图/dump |
| `common/utils/allure_utils.py` | 截图与文本附件、@step 装饰器 |
| `common/utils/ui_dump.py` | page_source 落盘 xml + Allure 附件 + 元素统计 |
| `common/logger.py` | 控制台 INFO + 文件 DEBUG 滚动 |
| `testcases/conftest.py` | CLI 参数注册、平台隔离 skip、session 级 driver fixture |
| `pages/*` | 业务页面对象(每个页面一个类, 方法即业务动作) |
| `scripts/*` | 一键 init / 跑批 / 报告 |

## 4. 关键设计

### 4.1 Driver 会话生命周期
- 整个 pytest session 只建**一个** driver(fixture scope=session), 避免反复冷启动, 提升冒烟/回归速度。
- teardown 统一 `DriverManager.quit()`, 异常也不残留进程。
- `newCommandTimeout` 默认 300s, 防止空闲会话被服务端误杀。

### 4.2 capabilities 决策链
```
--app 指定文件 → apps/ 自动扫描 → 直接启动已安装的配置包(appPackage/bundleId)
设备: --udid → config.local → config.global → Android 自动探测 adb devices
```
因此 "扔 App" 时通常**只需传文件路径**, 其余全自动。

### 4.3 PageObject 与双端定位符
- 一个屏幕一个类, 方法 = 业务动作(如 `login(user, pwd)`), 测试只调方法不断言细节。
- 元素 = 双端字典 `{"android": (By, v), "ios": (By, v)}`, `BasePage._resolve()` 按当前平台取值。
- 所有动作: 自动日志 + 等待 + 失败自动截图 + 中文描述(进入 Allure 步骤)。

### 4.4 通用冒烟(零元素依赖)—— AI 协作关键设计
`testcases/generic/test_app_smoke.py` 不需要任何元素知识:
1. 安装并启动(等首屏稳定) → 2. 首屏非空渲染 → 3. 静置稳定性(无崩溃)
4. **UI dump**: 把整页 hierarchy 存成 xml + 节点统计 → 5. 首屏截图。
产出物落到 `reports/dumps/` 与 `screenshots/`, 是后续**让 AI 看懂这个 App 页面**并生成 PageObject/用例的输入。

### 4.5 平台隔离与 demo 策略
- marker `android/ios` + conftest 自动 skip → 在任意平台跑全套命令都**不会红**。
- demo 用例默认排除(`--with-demo` 才跑), 保证日常执行干净。

### 4.6 配置分层
`global.yaml`(默认) ← 深合并 ← `local.yaml`(个人, gitignore) ← CLI(最高)。
个人模拟器序列号、被测 App 包名写 local.yaml, 换机器/同事互不干扰。

## 6. CI / 持续集成(建议)

```yaml
# .gitlab-ci.yml / GitHub Actions 思路
stages: [android, ios]
android job:
  script:
    - scripts/setup_env.sh
    - appium driver install uiautomator2
    - appium --address 127.0.0.1 --port 4723 &   # 启动 server
    - python -m pytest --platform android --app apps/demo.apk
    - allure generate allure-results -o reports/allure-report --clean
  artifacts:
    paths: [reports/allure-report, screenshots/, reports/dumps/]
ios job:      # 仅 macOS runner
  tags: [macos]
  script:
    - python -m pytest --platform ios --app apps/Demo.app
```

## 7. 平台限制与风险应对

| 风险/限制 | 说明 | 应对 |
| --- | --- | --- |
| Windows 无法跑 iOS | XCUITest 强依赖 Xcode | iOS 用例双端同构可维护、CI/远程 Mac 执行; Windows 上自动 skip |
| Android 碎片化(包名/activity 不同) | 不同版本 App 元素差异 | UI dump 先行, 元素字典集中管理 |
| 权限弹窗/系统弹窗 | 干扰定位与点击 | `autoGrantPermissions`、`autoAcceptAlerts`、脚本可控 |
| 元素定位不稳定 | 动态 id / 网络慢 | WebDriverWait 显式等待 + 失败自动截图 |
| App 升级/闪屏 | 首帧不稳定 | `launch_settle` 等待 + 通用冒烟先验证可启动 |
| 多设备混淆 | 多台 adb 设备 | 显式 `--udid`, 或 local.yaml 写死 |
