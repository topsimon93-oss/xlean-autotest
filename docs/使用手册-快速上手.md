# xLean Appium 自动化测试 —— 使用手册

> 面向「明天就要交付」的一线操作手册。不讲原理，只讲：每个节点是什么、怎么点、出问题看哪。

---

## 0. 一句话总览

你手里这套东西，本质是**两条测试线**，各有各的入口和产出：

| 线 | 测什么 | 成本 | 入口命令 | 产物 |
|---|---|---|---|---|
| **Appium 回归** | xLean App 的 13 条固定断言用例 | **零 token** | `run_full_pipeline.py --skip-artemis` | `pipeline_report.html` + `trend.html` |
| **Artemis 探索** | 手机系统级操作（电量/相机/WiFi 等） | 消耗 token | `run_full_pipeline.py --skip-appium` | 同上 + 截图证据 |

**你 99% 的时间只会用 Appium 那条线**（测 xLean，不花钱）。

## 1. 三个前置条件（每次跑之前，花 30 秒确认）

跑之前必须满足这三条，缺一条就失败：

### ① 真机已连（adb 能看到设备）

```powershell
adb devices
```

**期望输出**：一行 `57171FDCH009ZC   device`（注意是 `device` 不是 `unauthorized` 也不是 `offline`）

- 如果空 → 插 USB 线，手机点「允许 USB 调试」
- 如果 `unauthorized` → 手机弹窗点了「始终允许」
- 如果 `offline` → 拔了重插

### ② Appium Server 已起（监听 4723 端口）

```powershell
netstat -ano | findstr ":4723"
```

**期望**：能看到 `LISTENING`。

如果没起，开一个 PowerShell 窗口跑：

```powershell
cd C:\Users\xlean\WorkBuddy\2026-09-02-13-57-28\AppAutoTest
.\start_appium.ps1
```

这个窗口**保持开着**（Ctrl+C 才会停）。

### ③ （仅 Artemis 线需要）Artemis daemon 已起

```powershell
cd D:\projects\artemis
uv run artemis ui
```

同样**保持开着**。测 xLean 的 Appium 线**不需要**这个。

## 2. 跑一次完整测试（核心操作）

打开一个 PowerShell 窗口：

```powershell
cd C:\Users\xlean\WorkBuddy\2026-09-02-13-57-28\AppAutoTest
& ".\.venv\Scripts\python.exe" run_full_pipeline.py --skip-artemis
```

**为什么要用完整路径 `& ".\.venv\Scripts\python.exe"`？**
因为你系统里直接敲 `python` 会被 Windows 商店的占位符挡住，报 `Python was not found`。用项目自带的 venv 里的 python 就没事。

### 跑的时候你会看到什么

1. 手机屏幕**自己动**：反复打开 xLean → 进设置 → 返回 → 进账号页
2. 窗口滚动打印用例名
3. 全程 **12~20 分钟**（每条用例都要冷启动 App）

### 跑完的产物在哪

```
C:\Users\xlean\WorkBuddy\2026-09-02-13-57-28\AppAutoTest\reports\pipeline\
```

| 文件 | 是什么 | 什么时候看 |
|---|---|---|
| `pipeline_report.html` | **本次总报告**（每条用例明细+截图） | 每次跑完看 |
| `trend.html` | **历史趋势仪表盘**（通过率/稳定率/缺陷清单） | 想看长期质量时看 |
| `history.json` | 历史原始数据（自动累积） | 不用管，别删 |
| `appium_junit.xml` | pytest 原始结果 | 不用管 |

**最快看结果的方式**：双击 `pipeline_report.html`。

## 3. 怎么判断「跑对了还是跑挂了」

看窗口最后几行，会有 `X passed, Y failed`：

- **`13 passed, 0 failed`** → 全绿，健康 ✅
- **有 `failed`** → 看是几条、哪条，再打开报告看截图定位

判断「是否在跑」的两个可靠信号：
1. **手机屏幕自己在动**
2. **窗口在滚动打印用例名**

（光看 Appium 窗口刷 `GET /status` 那不算在跑，那是心跳。）

## 4. 常用变体命令

```powershell
# 只跑 Appium（测 xLean，零 token）★ 最常用
& ".\.venv\Scripts\python.exe" run_full_pipeline.py --skip-artemis

# 只跑 Artemis（测手机系统操作，消耗 token）

# 两条线都跑（全流程）
& ".\.venv\Scripts\python.exe" run_full_pipeline.py

# 不跑任何测试，用上次数据重新出报告（改完报告样式后用它刷新）
& ".\.venv\Scripts\python.exe" run_full_pipeline.py --report-only
```

## 6. 排障速查（踩过的坑，按出现频率排序）

| 现象 | 原因 | 处理 |
|---|---|---|
| `Python was not found` | 系统 PATH 没 python | 用完整路径 `& ".\.venv\Scripts\python.exe"` |
| `unauthorized` | USB 调试授权掉了 | 手机点「始终允许」 |
| 全部用例 ERROR，报 `instrumentation process is not running` | Artemis 之前把设备端 uiautomator2 搞崩了 | 强停设备端进程 + 重启 Appium（见下） |
| 卡 2 分钟不动 | 多进程抢设备 | 确认没有别的 pytest 在跑，杀干净重跑 |
| 设备名断言失败 | xLean 版本升级，设备名变了 | 定位器已改成前缀匹配，一般不用管 |
| `allure-results` 报 INTERNALERROR | 安全防护拦截批量删除 | 已内置自动改名规避，一般不会遇到 |

### 设备端 uiautomator2 崩溃的完整修复

```powershell
adb shell am force-stop io.appium.uiautomator2.server
adb shell am force-stop io.appium.uiautomator2.server.test
adb shell am force-stop io.appium.settings
# 然后重启 Appium（见 1.②）
```
