# xLean App 自动化测试 — 团队接入指南

> 面向「新测试伙伴从零接手」的一页纸说明。照着走，20 分钟内能在自己电脑上跑出和主仓库一致的结果。

---

## 一、你需要什么

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 | 真机 USB 调试在 Windows 上最顺 |
| Python | 3.9+（推荐 3.12） | 装时勾选 "Add to PATH" |
| Node.js | 18+（推荐 20/22） | 只用来跑 Appium Server |
| 手机 | 一台 xLean 真机 + USB 数据线 | 打开「开发者选项 → USB 调试」 |
| ADB | 随 Android Studio 或 platform-tools | 装完 `adb devices` 能看见设备即可 |

> ⚠️ 本框架**不依赖固定设备序列号**：`config/global.yaml` 里 `udid: null`，会自动选 `adb devices` 里的第一台设备。所以每个伙伴插自己的手机就能跑，不用改代码。

## 二、从零到跑通（6 步）

### 1. 拿代码

```bash
# 从云端仓库克隆（路径按你们实际的 git 地址替换）
git clone <你们的仓库地址> xlean-autotest
cd xlean-autotest
```

如果暂时没 git，直接解压别人发你的 `xlean-autotest.zip` 交付包也一样。

### 2. 一键初始化环境（Windows 双击或命令行）

```bash
scripts\setup_env.bat      # 建 .venv + 装依赖 + 生成 config/local.yaml
scripts\appium_install.bat # 装 Node 依赖：appium + uiautomator2 driver
```

这两个脚本会自己探测环境、缺什么补什么，跑完会打印检查汇总。

### 3. 改自己的被测 App 配置（关键一步）

每个人可能连的是**不同固件版本**的 xLean 机。打开 `config/local.yaml`，把包名/入口改成你机器上实际装的版本：

```yaml
android:
  app_package: ai.xlean.android.debug      # ← 改成你设备上的包名
  app_activity: ai.xlean.android.ui.MainActivity
```

> 怎么查包名？手机连上后执行：
> ```bash
> adb shell pm list packages | findstr xlean
> ```

### 4. 连设备 + 起 Appium Server

```bash
# 确认设备已识别（要显示 device，不是 unauthorized）
adb devices

# 起 Appium（保持这个窗口开着）
scripts\start_appium.bat
```

> 如果显示 `unauthorized`，手机上点「允许 USB 调试」后重跑 `adb devices`。

### 5. 跑测试

最省事 —— 双击项目根目录的 `一键测试xLean.bat`，自动跑完 12 条用例并弹出报告。

或者命令行：

```bash
.venv\Scripts\python.exe run_full_pipeline.py --skip-artemis
```

### 6. 看结果

- 完整报告：`reports/pipeline/pipeline_report.html`（双击浏览器打开，含截图证据）
- 趋势面板：`reports/pipeline/trend.html`（历史运行质量曲线、稳定率矩阵）

## 三、命令速查

| 想干什么 | 命令 |
|---|---|
| 跑全部 12 条 xLean 用例 | `一键测试xLean.bat` 或 `python run_full_pipeline.py --skip-artemis` |
| 只跑某一个用例 | `python -m pytest testcases/android/test_xlean_app.py::test_menu_open_close --platform android -v` |
| 只跑某一个文件 | `python -m pytest testcases/android/test_xlean_app.py --platform android -v` |
| 框架自检（不连设备） | `python -m pytest -m selfcheck` |
| 不跑测试、只看上次报告 | `python run_full_pipeline.py --report-only` |
| 清掉旧 allure 结果 | 手动把 `allure-results` 改名（脚本会自动让路） |

## 四、常见坑（团队实测）

| 症状 | 原因 | 解法 |
|---|---|---|
| `adb devices` 显示 `unauthorized` | 手机没授权 | 手机上点「允许 USB 调试」 |
| 第 1 条 PASSED，第 2 条起连续 ERROR | uiautomator2 instrumentation 崩 | 关掉 Appium 重起，再跑一次；别在跑的过程中杀 adb |
| 找不到「进入设备」等元素 | App 版本升级改了 UI | 见下方「App 升级了怎么办」 |
| 中文输出乱码 | 控制台编码问题 | 用 PowerShell 或 Windows Terminal 跑，别用老 cmd |

---

## 五、App 升级了怎么办（维护须知）

xLean 每次发版，首页/设置页 UI 可能变。维护套路：

1. 先跑一轮，看哪些用例 FAIL；
2. 对 FAIL 用例，用 `adb shell "uiautomator dump /data/local/tmp/ui.xml"` 抓当前页面结构；
3. 对比 `pages/android_xlean_page.py` 里的定位符，更新过时的 `text=` / `content-desc=`；
4. **优先用「稳定入口」断言**（如「进入设备」），别死磕会变的文案（如设备名「xLean TR1」）。

> 2026-10-10 实战记录：App 升到 V0.22.6.0 后首页把「xLean TR1」设备名改成了「进入设备」入口，3 条用例因此 FAIL。已改为用「进入设备」判断，这是典型案例。

## 六、目录速览

```
AppAutoTest/
├── 一键测试xLean.bat          # 双击即跑（最常用入口）
├── run_full_pipeline.py       # 全流程编排（跑测试 + 出报告 + 记趋势）
├── testcases/android/         # xLean 测试用例（12 条）
├── pages/android_xlean_page.py # 页面对象（元素定位都在这）
├── common/                    # 驱动管理、日志、allure 工具
├── config/                    # global.yaml(共享) + local.yaml(个人私有)
├── reports/pipeline/          # 产出：报告 + 趋势 + 历史
└── docs/                      # 方案、流程图、接入指南
```
